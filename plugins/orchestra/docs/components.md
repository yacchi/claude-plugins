# Components

Detailed role of every file in the plugin. The README has a one-line summary of each.

| File | Role | Model |
|---|---|---|
| `agents/orchestra-light.md` | Mechanical implementation worker. Implements literally, no scope expansion, self-verifies before reporting. | Haiku |
| `agents/orchestra-deep.md` | Design-sensitive implementation worker for tasks with real design latitude (algorithm choice, API shape, tradeoffs). Decides within the contract's bounds and reports decisions with rationale. | Opus |
| `agents/orchestra-review.md` | Adversarial review. Re-runs the worker's tests, lists ≥3 likely implementation mistakes and probes each with a throwaway test (keeping only those that found a defect or guard a likely, silent mistake, reported in `tests_kept` with the test/implementation line counts), returns a strict verdict. Two hard boundaries as of v0.14.0: it reviews but never repairs (`Write` is for its own probe files only — patching the implementation destroys the signal), and a FAIL requires a cited contract violation, with everything else demoted to non-blocking `optional_hardening`. Classifies findings by defect family and sweeps siblings before reporting; supports an incremental re-gate mode and a hard inspection budget. | Sonnet |
| `agents/orchestra-delegate.md` | Middle-manager fallback for environments without Dynamic Workflows. Holds context across retry rounds, dispatches each implementation round itself via `agent-exec dispatch --class light` (no relay needed — it already has Bash) rather than spawning a Claude implementer directly, drives review→retry, escalates only genuine ambiguity. | Sonnet |
| `skills/run/SKILL.md` | The playbook (`/run`, or `orchestra:run` cross-plugin). Read by the instructor. Instructor code of conduct, express-lane criteria, capability-class table, the one model-pinning rule, the workflow template, worker-prompt requirements, and short condensed sections on latency, fallback, configuration, telemetry, gate discipline, and isolation — each pointing at the reference file that holds the detail. Deliberately lean (English, for token efficiency): it is loaded on every orchestrated run, so as of v0.12.0 rationale and detail live in `references/` and only rules that change what the instructor *does* stay inline. | — |
| `skills/run/references/authoring.md` | Detail split out of the playbook in v0.12.0 (English, verbatim): same-tree parallelism safety and `agentType` resolution, shortening the per-task critical path (overlapping adversarial-test authoring with implementation, never serializing independent work behind a barrier, sizing tasks to the concurrency width), prompt density, the measured PoC findings, and the no-Workflow `orchestra-delegate` fallback shape. Not loaded automatically; read while writing a workflow script. | — |
| `skills/run/references/gates.md` | New in v0.14.0 (English): why each gate rule exists — the gold-plating reviewer as the most expensive failure mode, why defects arrive in families, why a re-gate is incremental and why `new_family` stops the loop (and when a third round *is* right), the escalation ladder in both directions, why corrections go to a fresh worker while the delegate is resumed, and invocation budgets as a diagnostic. Not loaded automatically. | — |
| `skills/run/references/isolation.md` | New in v0.14.0, reframed in v0.16.0 (English): §0 makes worktree isolation the default whenever the tree is dirty (the accident data, why prose prohibitions lose, and the `agent-exec isolate` lifecycle), followed by baseline/checkpoint mechanics and jj recovery, branch hygiene (disposable descendants, a clean PR branch built from the accepted diff), worktree-isolated parallelism and supervisor merge, competing implementations and how to read their divergence, verifying on a context-free integration tree, and front-loading approvals for non-interactive workers. Not loaded automatically. | — |
| `skills/run/references/config.md` | Detail split out of the playbook in v0.12.0 (English, verbatim): the four-layer config schema and deep-merge algorithm (plus its pre-v0.11.0 upgrade trap), `agent-exec route`/`dispatch` gating, external-executor dispatch mechanisms and the `dispatch: cli` sandboxing caveat, `enforcement.light_class`/`worker_vcs`/`worker_tree`/`turn_edits` and their escape hatches, and the full telemetry field allowlist and CLI. Not loaded automatically; read only when a configuration question actually arises. | — |
| `skills/run/references/programme.md` | New in v0.31.0 (English). Programme-scale runs — dozens of session-sized packages with dependencies: the read-only planning workflows (audit → verify → critic → synthesize, design → critique → revise, competing designs → judge, reconcile → cross-check, pre-scheduling reality check) with a role→model table, the package schema, and a complete scheduler template (dependency and file-overlap gating, rolling integration base via `--workdir <integration worktree>`, serial Sonnet integrator over `isolate integrate`, periodic full verification that pauses scheduling on red, carry-over triage, chunk budget with a resumable pending set) that reuses `runTask()` per package. Not loaded automatically. | — |
| `skills/cleanup/SKILL.md` | New in v0.30.0. Companion cleanup skill (`/cleanup`, or `orchestra:cleanup` cross-plugin). Drives `agent-exec isolate sweep` to reclaim leftover orchestra worktrees **repo-wide** — the ones `SessionEnd` never got to because the session crashed, predates the hook, ran with it disabled, or left a dirty tree behind on purpose. Reports a dry run first, keeps anything holding uncollected work, and offers `isolate diff`/`collect`/`--force` per dirty tree rather than deciding for the user. | — |
| `skills/setup/SKILL.md` | Companion config skill (`/setup`, or `orchestra:setup` cross-plugin). Detects Codex/pi CLI + agent availability, then interactively edits `.claude/orchestra.yaml` (project) or `~/.claude/orchestra.yaml` (user) — enabling/disabling executors, choosing scope, and migrating an old `orchestra.json`. Never runs the pipeline itself. | — |
| `skills/run/references/external-executors.md` | Operational reference for external executors (Japanese) — Codex's Sol/Terra/Luna + effort policy and default `dispatch: cli` CLI/session-resume recipe (`dispatch: agent`/`codex:codex-rescue` as an override), pi's model ids/providers and CLI usage recipe (including `--session` continuation), the removed-executors note, and official per-token pricing for Codex/Copilot-metered models/Claude. Not loaded automatically; read on demand when actually dispatching to Codex/pi. | — |
| `skills/run/references/poc-findings.md` | The full research log behind the external-executor model policy (Japanese) — every PoC round, bug found, and policy change, with the reasoning. Not loaded automatically; read on demand. | — |
| `skills/run/references/poc-fixtures/` | Reusable fixtures for every PoC round (task specs, verification harnesses, reference/buggy implementations) so a new model can be re-tested and compared without rebuilding anything from scratch. See its own `README.md` for exact reproduction commands. | — |
| `tools/agent_exec.py` (`agent-exec` on `PATH` after `agent-exec install`) | The `agent-exec` CLI. `route --class <cls>` and `dispatch --class <cls> ... --capture` execute the `priority` walk deterministically (config load → enabled/binary/`ready.<x>.ok`/`class_policy`/`--exhausted` gating → optional CLI run) so the instructor never performs the walk by hand — it asks, via one relay agent, and branches on the JSON reply. Also `config`, `doctor`, `run`, `install`, `usage`, `telemetry`, and (v0.31.0) `shelf`, the per-worktree replacement for `git stash`. See `skills/run/references/config.md` and `references/external-executors.md` §5. | — |
| `hooks/hooks.json` + `hooks/inject-router.sh` | Auto-activation. Injects the `<orchestra-router>` lane-classification protocol into context at session start and re-injects it after `/clear`, resume, and compaction. Also persists the model-gate verdict to a per-session state file for the reminder hook. | — |
| `hooks/remind-router.sh` | Per-prompt recency. A `UserPromptSubmit` hook that appends a ~45-token router reminder on every user prompt of instructor-model sessions, so the classification step stays adjacent to the request it must classify even in very long sessions. Gated via the state file written by `inject-router.sh`; emits nothing on cheap-model sessions. | — |
| `hooks/enforce-router.sh` | Opt-in (`enforcement.light_class: "block"`, ships `"off"` — quote the value, YAML 1.1 reads a bareword `off` as boolean) `PreToolUse` guardrail — a **nudge with a guaranteed escape, never a hard wall**. Fires only on a *generic* Claude implementer call (no `subagent_type`, or `subagent_type` in `general-purpose`/`claude`, at a Haiku-class model) while `agent-exec route --class light` reports a ready non-Claude executor; naming any other specific `subagent_type` is itself a carve-out (the Agent tool has no per-call tool-restriction params, so a named agent is how tool access/system prompt get pinned — an external executor can't substitute for that). Denies **at most once per session, full stop** — not per prompt/task, since this plugin's own retry convention mutates the prompt every round. Other escape hatches: a `[orchestra:allow-claude: reason]` marker, and `ORCHESTRA_ENFORCEMENT=off` plus fail-open on any uncertainty. See `skills/run/references/config.md`. | — |
| `hooks/guard-worker-vcs.sh` | On by default (`enforcement.worker_vcs: "block"`). A `PreToolUse` guard denying destructive VCS commands (`checkout -- <paths>`, `checkout .`, `restore` without `--staged`, `reset --hard/--merge/--keep`, `clean -f`, `stash push`, `worktree remove --force`) when they come from a **subagent** and target a tree that is not one of orchestra's own (`orchestra/*` branch). `git stash` push/pop/apply/drop/clear is denied even inside orchestra's own worktrees (v0.31.0): `refs/stash` is shared by every worktree, and parallel workers popping it have swapped each other's changes. Ships on, unlike `enforce-router.sh`, because it prevents data loss rather than steering a cost decision. The main thread is untouched, a worker inside its own worktree is untouched, `orchestra-delegate` (which owns snapshots and rollbacks) is exempt, and heredoc/quoted text that merely *mentions* the commands is not mistaken for running them. Escapes: `[orchestra:allow-vcs: reason]`, `ORCHESTRA_VCS_GUARD=off`, and fail-open on any uncertainty. | — |
| `hooks/guard-worker-tree.sh` | On by default (`enforcement.worker_tree: "block"`). A `PreToolUse` guard denying a **worker subagent that already has an orchestra worktree of its own** (a `git worktree list` branch under `orchestra/<session8>/`) from writing into the user's **main** working tree — the first worktree git lists. `Edit`/`Write`/`MultiEdit`/`NotebookEdit` are covered with zero parsing via `tool_input.file_path`/`notebook_path`; `Bash` is deliberately narrow (`> PATH`, `>> PATH`, `tee PATH`, `sed -i PATH`, after the same heredoc/quoted-string stripping) and `cp`/`mv`/`rm`/interpreter invocations are **not** analyzed on purpose. Paths are compared by components after `realpath`, so symlinks, `..` escapes, and the `/repo-worktrees/x` vs `/repo` prefix trap all resolve correctly. The main thread has no `agent_id` and is untouched, `orchestra-delegate` (which integrates worker output) is exempt, and a session with no orchestra worktree never triggers it. Escapes: `[orchestra:allow-tree: reason]`, `ORCHESTRA_TREE_GUARD=off`, and fail-open on any uncertainty. | — |
| `hooks/guard-worktree-lease.sh` | New in v0.31.0, on by default (`enforcement.worktree_lease: "block"`). `PreToolUse` + `SubagentStop`: one writing subagent per **linked** worktree. The first subagent write (Edit/Write/MultiEdit/NotebookEdit, or Bash running a state-changing git verb or redirecting into a file) takes a lease stored in the worktree's own git dir; a different subagent writing there while the holder wrote within `worktree_lease_window` seconds (default 120) is denied and told to stop if it is a duplicate; `SubagentStop` releases the holder's leases so back-to-back rounds are never blocked. Reads, tests, and `git diff` never touch the lease; the main worktree, the main thread, and `orchestra-delegate` are untouched. Escapes: `[orchestra:allow-lease: reason]`, `ORCHESTRA_LEASE_GUARD=off`, fail-open. | — |
| `hooks/count-turn-edits.sh` | Turn-size tripwire (`enforcement.turn_edits`, default 8). A `PostToolUse` hook counting the **main thread's** edits within one turn; on crossing the threshold it injects one request to re-classify into the orchestrated lane. It never blocks an edit. Turn-level transcript analysis found orchestra invoked in 1 of the 102 turns that went on to hand-edit 10+ files: the prompts producing those turns ("作業を続けて", "実装して", "y") look small at classification time and only reveal their size once work is underway. Subagent edits are not counted — that is the delegation working. Since v0.41.0 it fires a second, firmer time at twice the threshold, saying the "I already hold the spec" exemption has expired — a 30-day, two-machine review saw models answer the first nudge with "staying EXPRESS" and carry on to 37 edits in one turn. Silent in cheap-model sessions; `ORCHESTRA_TURN_GUARD=off` disables it. | — |
| `hooks/nudge-opus-generalist.sh` | New in v0.41.0, on by default (`enforcement.opus_generalist: "nudge"`). A `PreToolUse` hook that denies **once per session** a `general-purpose` subagent that would run on the instructor's own Opus/Fable model — named `model: opus`, or `model` omitted, which inherits it — and says how to proceed: `model: "sonnet"` for read-only work, `orchestra:run` for anything that writes code. The same review found 88 of 207 generalist spawns on Opus-class models (about 1.58M output tokens), roughly half of them read-only investigation, so this is a nudge and never a wall: the retry is never blocked, `[orchestra:allow-opus: <reason>]` lets a deliberate spawn through, and the kill switches are `ORCHESTRA_OPUS_NUDGE=off` or `enforcement.opus_generalist: "off"`. Only instructor-model sessions are in scope. | — |
| `hooks/cleanup-worktrees.sh` | On by default (`enforcement.session_cleanup: "on"`). A `SessionEnd` hook that removes the finishing session's orchestra worktrees (`agent-exec isolate remove --session <id>`), keeping any that still hold uncollected changes — a dirty worktree is the only record of what a worker tried. As of v0.30.0 this is a **backstop**, not the mechanism: the pipeline sweeps at run end instead, since a killed or crashed session never reaches `SessionEnd` at all. An unrecognized config value falls back to `"on"`; `ORCHESTRA_SESSION_CLEANUP=off` disables it regardless of config. | — |
| `examples/orchestra.yaml` | Sample configuration file (YAML, fully commented). Copy to `.claude/orchestra.yaml` (project) or `~/.claude/orchestra.yaml` (user) to override model tiers, declare external executors (now `enabled: true` by default), or set `enforcement.light_class`/`worker_vcs`/`turn_edits`/`session_cleanup`, or use `/setup` to author it interactively. | — |

## Dashboard (`agent-exec ui`)

`agent-exec ui --open` starts a local, token-protected web page on 127.0.0.1 (the `orchestra:ui` skill wraps it). It shows every registered `agent-exec wave` run - packages, needs, the mechanical-stage timeline - plus worktrees, recent dispatches, cooldowns, running executors, linked context/spec files, and 24-hour usage, updating live over Server-Sent Events. It only reads files orchestra already writes, so it costs no tokens; a "Stop wave" button drops the wave's `STOP` flag. It exits after 30 idle minutes, or on `agent-exec ui --stop`.
`agent-exec wave run` prints the dashboard URL at startup unless `--no-ui` or `ORCHESTRA_WAVE_NO_UI=1` is set.
