# Components

Detailed role of every file in the plugin. The README has a one-line summary of each.

| File | Role | Model |
|---|---|---|
| `agents/orchestra-light.md` | Mechanical implementation worker. Implements literally, no scope expansion, self-verifies before reporting. | Haiku |
| `agents/orchestra-deep.md` | Design-sensitive implementation worker for tasks with real design latitude (algorithm choice, API shape, tradeoffs). Decides within the contract's bounds and reports decisions with rationale. | Opus |
| `agents/orchestra-review.md` | Adversarial review. Re-runs the worker's tests, lists ≥3 likely implementation mistakes and probes each with a throwaway test (keeping only those that found a defect or guard a likely, silent mistake, reported in `tests_kept` with the test/implementation line counts), returns a strict verdict. Two hard boundaries as of v0.14.0: it reviews but never repairs (`Write` is for its own probe files only — patching the implementation destroys the signal), and a FAIL requires a cited contract violation, with everything else demoted to non-blocking `optional_hardening`. Classifies findings by defect family and sweeps siblings before reporting; supports an incremental re-gate mode and a hard inspection budget. | Sonnet |
| `agents/orchestra-delegate.md` | Middle-manager fallback for environments without Dynamic Workflows. Holds context across retry rounds, dispatches each implementation round itself via `agent-exec dispatch --class light` (no relay needed — it already has Bash) rather than spawning a Claude implementer directly, drives review→retry, escalates only genuine ambiguity. | Sonnet |
| `agents/orchestra-scout.md` | Budgeted read-only scout, spawned only by `orchestra-planner`. Answers one scoped reading question about named files with `path:line` citations, in at most 30 lines and ending with an `Unchecked:` line. Tools `Read`, `Grep`, `Glob`, `Bash` (read-only commands only); `maxTurns` 17. The fan-out guard allows 15 tool calls and denies the rest ("answer with what you have"). Never edits, never spawns agents, never calls the advisor. | Sonnet (Haiku for pure file location) |
| `agents/orchestra-checker.md` | Budgeted evidence checker, spawned only by `orchestra-planner`. Reads only the `file:line` lines it is handed and returns confirmed / refuted / corrected per claim, without re-reading the area. Tools `Read`, `Grep`; `maxTurns` 9. The fan-out guard allows 8 tool calls. Never calls the advisor. | Sonnet |
| `skills/run/SKILL.md` | The playbook (`/run`, or `orchestra:run` cross-plugin). Read by the instructor. Instructor code of conduct, express-lane criteria, capability-class table, the one model-pinning rule, the workflow template, worker-prompt requirements, and short condensed sections on latency, fallback, configuration, telemetry, gate discipline, and isolation — each pointing at the reference file that holds the detail. Deliberately lean (English, for token efficiency): it is loaded on every orchestrated run, so as of v0.12.0 rationale and detail live in `references/` and only rules that change what the instructor *does* stay inline. | — |
| `skills/run/references/authoring.md` | Detail split out of the playbook in v0.12.0 (English, verbatim): same-tree parallelism safety and `agentType` resolution, shortening the per-task critical path (overlapping adversarial-test authoring with implementation, never serializing independent work behind a barrier, the size gate that splits long poles before dispatch, the ownership pre-check), prompt density, the measured PoC findings, and the no-Workflow `orchestra-delegate` fallback shape. Not loaded automatically; read while writing a workflow script. | — |
| `skills/run/references/gates.md` | New in v0.14.0 (English): why each gate rule exists — the gold-plating reviewer as the most expensive failure mode, why defects arrive in families, why a re-gate is incremental and why `new_family` stops the loop (and when a third round *is* right), the escalation ladder in both directions, why corrections go to a fresh worker while the delegate is resumed, and invocation budgets as a diagnostic. Not loaded automatically. | — |
| `skills/run/references/isolation.md` | New in v0.14.0, reframed in v0.16.0 (English): §0 makes worktree isolation the default whenever the tree is dirty (the accident data, why prose prohibitions lose, and the `agent-exec isolate` lifecycle), followed by baseline/checkpoint mechanics and jj recovery, branch hygiene (disposable descendants, a clean PR branch built from the accepted diff), worktree-isolated parallelism and supervisor merge, competing implementations and how to read their divergence, verifying on a context-free integration tree, and front-loading approvals for non-interactive workers. Not loaded automatically. | — |
| `skills/run/references/config.md` | Detail split out of the playbook in v0.12.0 (English, verbatim): the four-layer config schema and deep-merge algorithm (plus its pre-v0.11.0 upgrade trap), `agent-exec route`/`dispatch` gating, external-executor dispatch mechanisms and the `dispatch: cli` sandboxing caveat, `enforcement.light_class`/`worker_vcs`/`worker_tree`/`turn_edits` and their escape hatches, and the full telemetry field allowlist and CLI. Not loaded automatically; read only when a configuration question actually arises. | — |
| `skills/run/references/programme.md` | New in v0.31.0 (English). Programme-scale runs — dozens of session-sized packages with dependencies: the read-only planning workflows (audit → verify → critic → synthesize, design → critique → revise, competing designs → judge, reconcile → cross-check, pre-scheduling reality check) with a role→model table, the package schema, and a complete scheduler template (dependency and file-overlap gating, rolling integration base via `--workdir <integration worktree>`, serial Sonnet integrator over `isolate integrate`, periodic full verification that pauses scheduling on red, carry-over triage, chunk budget with a resumable pending set) that reuses `runTask()` per package. Not loaded automatically. | — |
| `skills/cleanup/SKILL.md` | New in v0.30.0. Companion cleanup skill (`/cleanup`, or `orchestra:cleanup` cross-plugin). Drives `agent-exec isolate sweep` to reclaim leftover orchestra worktrees **repo-wide** — the ones `SessionEnd` never got to because the session crashed, predates the hook, ran with it disabled, or left a dirty tree behind on purpose. Reports a dry run first, keeps anything holding uncollected work, and offers `isolate diff`/`collect`/`--force` per dirty tree rather than deciding for the user. | — |
| `skills/setup/SKILL.md` | Companion config skill (`/setup`, or `orchestra:setup` cross-plugin). Detects pi CLI availability, then interactively edits `.claude/orchestra.yaml` (project) or `~/.claude/orchestra.yaml` (user) — enabling/disabling executors, choosing scope, and converting an old `orchestra.json` on request. Never runs the pipeline itself. | — |
| `skills/run/references/external-executors.md` | Operational reference for external executors (Japanese) — pi's model ids/providers and CLI usage recipe (including `--session` continuation), the removed-executors note, and official per-token pricing for Copilot-metered models/Claude. Not loaded automatically; read on demand when actually dispatching to pi. | — |
| `skills/run/references/poc-findings.md` | The full research log behind the external-executor model policy (Japanese) — every PoC round, bug found, and policy change, with the reasoning. Not loaded automatically; read on demand. | — |
| `skills/run/references/poc-fixtures/` | Reusable fixtures for every PoC round (task specs, verification harnesses, reference/buggy implementations) so a new model can be re-tested and compared without rebuilding anything from scratch. See its own `README.md` for exact reproduction commands. | — |
| `bin/agent-exec` | POSIX-sh entry point that Claude Code puts on the Bash tool's `PATH` (no shim needed inside Claude Code). Resolves its own real directory through symlinks and execs `../tools/agent-exec`. | — |
| `tools/agent-exec` (`agent-exec` on `PATH` after `agent-exec install`; `install` is for shells outside Claude Code, which may not get the plugin's `bin/`, pi workers among them) | The POSIX-sh bootstrap and the stable path the installed shim points at (it resolves symlinks to itself). Runs the Go implementation in `tools/agentexec/`: builds it on first use with `AGENT_EXEC_GO`, else `go` on `PATH`, else `mise exec go@<.go-version>`, and caches the binary per source hash (hash includes OS and CPU arch) under `${XDG_CACHE_HOME:-~/.cache}/claude-orchestra/agent-exec/<sha256>/` (keeps the two previous builds; `AGENT_EXEC_BIN` overrides). Without a toolchain it exits 127 with install guidance. | — |
| `tools/agentexec/` | New in v0.55.0 (replaces the Python implementation). The `agent-exec` CLI in Go. `route --class <cls>` and `dispatch --class <cls> ...` execute the `priority` walk deterministically (config load → enabled/binary/`ready.<x>.ok`/`class_policy`/`--exhausted` gating → optional CLI run) so the instructor never performs the walk by hand — it asks, via one relay agent, and branches on the JSON reply; `dispatch --executor pi --model M --effort E` runs one executor directly. Also `config`, `doctor` (with the `build` block: binary, source hash, Go version), `install`, `usage`, `telemetry`, `shelf` (the per-worktree replacement for `git stash`), `isolate` (including `isolate land`, which squashes a source onto the user's branch as one commit with the user's identity: `--task <into>` for a wave's integration tree, `--path <worktree>` for an Agent-tool worktree), `hook` (`session-start` and `seen`, the command hooks), `check`, `wave`, `approvals`, `pi login`, `sandbox` (Seatbelt / bubblewrap / Landlock policy, learned grants, srt network), `tools status\|install` (pinned pi, herdr and srt in orchestra's state dir), the run watchdog, and the `usage` price list. `hook context` returns a session's or agent's transcript context for `hooks/guards/resume.ts`. `usage --run <id>` also counts the hosted Claude sessions recorded under that run id (`<state dir>/hosted/<run id>.txt`; each hosted session starts with its own `--session-id`). Hosted workers run with `CLAUDE_CODE_DISABLE_ADVISOR_TOOL=1` in both `user_config` modes. Before every workspace create, the herdr executor re-checks the herdr server and re-attaches or restarts it when it is gone. Conformance scenarios with goldens live in `testdata/conformance/` (compared semantically: JSON by value, exit codes exactly; refresh after an intended change with `go test ./internal/conformance -update`). See `skills/run/references/config.md` and `references/external-executors.md` §5. | — |
| `hooks/hooks.json` → `hooks/orchestra.ts` | The plugin's one hooks module, registered by `hooks/hooks.json`. It listens only to events Claude Code does not hold from user-tier mods: `tool.call` (the guards, plus the turn-size nudge, which rides on an edit's result as `context`), `turn.start` (main-loop turn ids and the heartbeat stamp), `turn.complete` (lease release for subagents, and the opt-in ask detection on the main loop), `prompt.submit` (the user's opt-in) and `session.end` (session worktree cleanup). It hands each event to the rule files below (`hooks/guards/`, `hooks/router/`, `hooks/lifecycle/`, sharing `hooks/lib/`, with one `agent-exec config --json` lookup per session). The session verdict comes from `$.session.model()` and `$.session.root()`. SessionStart is not handled here: it is a command hook (see `hookrun` below). The module also registers the HUD (`hooks/hud.ts`, its wave pane and band drawn by `hooks/progress.tsx`), which adds its own `agent.spawn`, `turn.complete` and Bash-only `tool.call` hooks, and the `session.start`, `command.run` (`/orchestra:progress`), `ui.close` and `ui.render` (`Pane`, `AbovePrompt`) hooks of the progress views. Its hooks run the plugin's own `bin/agent-exec` (`$.plugin.root`), never the `agent-exec` found on `PATH`. | — |
| `tools/agentexec/internal/hookrun/` (assets `assets/router.md`, `assets/selfgate.md`, `assets/worker.md`) | Auto-activation. `agent-exec hook session-start` is a SessionStart command hook registered in `hooks/hooks.json` next to the module, for the `startup`, `resume`, `clear` and `compact` sources. It injects the `<orchestra-router>` lane-classification protocol into context, so the router survives new sessions, `/clear`, resume, and compaction. The model gate is unchanged: Opus/Fable get the full router, a missing model gets the self-gated variant, other models get nothing. A session that starts inside an orchestra task worktree (created or adopted, not an integration target) — a herdr/Orca-hosted `wave run` worker, found with `isolate.TaskTree` — gets an `<orchestra-worker>` notice instead, on any model; the verdict `worker` turns off the turn tripwire for it. It is a command rather than a module listener because on Team/Enterprise logins and machines with managed settings Claude Code seats `cc-plugin-sec-default` outermost, which continues every `classic.*` event past user-tier mods, so a `classic.SessionStart` listener never runs there; plugin command hooks run as before. The command always exits 0. The module's per-session stamps are recorded by its sibling command `agent-exec hook seen`. | — |
| `hooks/guards/light-class.ts` | Opt-in (`enforcement.light_class: "block"`, ships `"off"` — quote the value, YAML 1.1 reads a bareword `off` as boolean) `PreToolUse` guardrail — a **nudge with a guaranteed escape, never a hard wall**. Fires only on a *generic* Claude implementer call (no `subagent_type`, or `subagent_type` in `general-purpose`/`claude`, at a Haiku-class model) while `agent-exec route --class light` reports a ready non-Claude executor; naming any other specific `subagent_type` is itself a carve-out (the Agent tool has no per-call tool-restriction params, so a named agent is how tool access/system prompt get pinned — an external executor can't substitute for that). Denies **at most once per session, full stop** — not per prompt/task, since this plugin's own retry convention mutates the prompt every round. Other escape hatches: a `[orchestra:allow-claude: reason]` marker, and `ORCHESTRA_ENFORCEMENT=off` plus fail-open on any uncertainty. See `skills/run/references/config.md`. | — |
| `hooks/guards/worker-vcs.ts` | On by default (`enforcement.worker_vcs: "block"`). A `PreToolUse` guard denying destructive VCS commands (`checkout -- <paths>`, `checkout .`, `restore` without `--staged`, `reset --hard/--merge/--keep`, `clean -f`, `stash push`, `worktree remove --force`) when they come from a **subagent** and target a tree that is not one of orchestra's own (`orchestra/*` branch). `git stash` push/pop/apply/drop/clear is denied even inside orchestra's own worktrees (v0.31.0): `refs/stash` is shared by every worktree, and parallel workers popping it have swapped each other's changes. Ships on, unlike `hooks/guards/light-class.ts`, because it prevents data loss rather than steering a cost decision. The main thread is untouched, a worker inside its own worktree is untouched, `orchestra-delegate` (which owns snapshots and rollbacks) is exempt, and heredoc/quoted text that merely *mentions* the commands is not mistaken for running them. Escapes: `[orchestra:allow-vcs: reason]`, `ORCHESTRA_VCS_GUARD=off`, and fail-open on any uncertainty. | — |
| `hooks/guards/worker-tree.ts` | On by default (`enforcement.worker_tree: "block"`). A `PreToolUse` guard denying a **worker subagent that already has an orchestra worktree of its own** (a `git worktree list` branch under `orchestra/<session8>/`) from writing into the user's **main** working tree — the first worktree git lists. `Edit`/`Write`/`MultiEdit`/`NotebookEdit` are covered with zero parsing via `tool_input.file_path`/`notebook_path`; `Bash` is deliberately narrow (`> PATH`, `>> PATH`, `tee PATH`, `sed -i PATH`, after the same heredoc/quoted-string stripping) and `cp`/`mv`/`rm`/interpreter invocations are **not** analyzed on purpose. Paths are compared by components after `realpath`, so symlinks, `..` escapes, and the `/repo-worktrees/x` vs `/repo` prefix trap all resolve correctly. The main thread has no `agent_id` and is untouched, `orchestra-delegate` (which integrates worker output) is exempt, and a session with no orchestra worktree never triggers it. Escapes: `[orchestra:allow-tree: reason]`, `ORCHESTRA_TREE_GUARD=off`, and fail-open on any uncertainty. | — |
| `hooks/guards/worktree-lease.ts` | New in v0.31.0, on by default (`enforcement.worktree_lease: "block"`). `PreToolUse` + `SubagentStop`: one writing subagent per **linked** worktree. The first subagent write (Edit/Write/MultiEdit/NotebookEdit, or Bash running a state-changing git verb or redirecting into a file) takes a lease stored in the worktree's own git dir; a different subagent writing there while the holder wrote within `worktree_lease_window` seconds (default 120) is denied and told to stop if it is a duplicate; `SubagentStop` releases the holder's leases so back-to-back rounds are never blocked. Reads, tests, and `git diff` never touch the lease; the main worktree, the main thread, and `orchestra-delegate` are untouched. Escapes: `[orchestra:allow-lease: reason]`, `ORCHESTRA_LEASE_GUARD=off`, fail-open. | — |
| `hooks/router/turn-edits.ts` | Turn-size tripwire (`enforcement.turn_edits`, default 8). The module counts the **main thread's distinct files** edited within one turn (repeat edits to one file count once) and, on crossing the threshold, attaches one request to re-classify into the orchestrated lane as `context` on that edit's `tool.call` result (not a `PostToolUse` hook). It never blocks an edit. Turn-level transcript analysis found orchestra invoked in 1 of the 102 turns that went on to hand-edit 10+ files: the prompts producing those turns ("作業を続けて", "実装して", "y") look small at classification time and only reveal their size once work is underway. Subagent edits are not counted — that is the delegation working. Since v0.41.0 it fires a second, firmer time at twice the threshold, saying the "I already hold the spec" exemption has expired — a 30-day, two-machine review saw models answer the first nudge with "staying EXPRESS" and carry on to 37 edits in one turn. Silent in cheap-model sessions; `ORCHESTRA_TURN_GUARD=off` disables it. | — |
| `hooks/guards/opus-generalist.ts` | New in v0.41.0, on by default (`enforcement.opus_generalist: "nudge"`). A `PreToolUse` hook that denies **once per session** a `general-purpose` subagent that would run on the instructor's top tier — `model` omitted (which inherits the session's Opus/Fable model), or named `model: fable`; a named `model: opus` is a deliberate choice and is allowed — and says how to proceed: `model: "sonnet"` for read-only work, `orchestra:run` for anything that writes code. The same review found 88 of 207 generalist spawns on Opus-class models (about 1.58M output tokens), roughly half of them read-only investigation, so this is a nudge and never a wall: the retry is never blocked, `[orchestra:allow-opus: <reason>]` lets a deliberate spawn through, and the kill switches are `ORCHESTRA_OPUS_NUDGE=off` or `enforcement.opus_generalist: "off"`. Only instructor-model sessions are in scope. | — |
| `hooks/guards/usage.ts` | On by default (`enforcement.usage_guard: 90`; `"off"` or `ORCHESTRA_USAGE_GUARD=off` disables). A `PreToolUse` guard denying `Agent`, `Task` and `Workflow` calls while the plan's five-hour window (`five_hour` in `$.session.usage().rateLimits`) is at or above the threshold. Added after the 2026-10-26 runaway, where 23 planner children used 89% of an hour's 388M tokens: cache reads count against the plan limit, so new spawns are refused once the window is nearly spent. `orchestra:orchestra-wave` and `orchestra:orchestra-relay` are exempt. Escape: `[orchestra:allow-usage: <reason>]` in a main-thread Agent call's description or prompt, twice per session. Fails open without a reading. Distinct from `usage_routing.thresholds.five_hour` (80), which re-routes and never denies. Hosted Claude workers that `wave run` starts are not Agent spawns and are not covered. | — |
| `hooks/guards/fanout.ts` | On by default (`enforcement.fanout`: `children` 6, `concurrent` 2, `scout_calls` 15, `checker_calls` 8). A `PreToolUse` guard limiting what an `orchestra-planner` spawns. It may spawn only `orchestra:orchestra-scout` and `orchestra:orchestra-checker`, at most 6 children per planner and 2 alive at once. Each scout gets 15 tool calls and each checker 8; every further call is denied with "answer with what you have". The 2026-10-26 runaway (23 Sonnet children, 14–19 at once for 45 minutes) had no such caps. `maxTurns` in the agent files is the backstop. `enforcement.fanout: "off"` or `ORCHESTRA_FANOUT_GUARD=off` disables it. There is no per-call escape: a planner must not lift its own cap. | — |
| `hooks/guards/resume.ts` | On by default (`enforcement.resume_max_tokens: 100000`; `"off"`, `0` or `ORCHESTRA_RESUME_GUARD=off` disables). A `PreToolUse` guard denying `SendMessage` to an agent whose last response carried a context at or above the limit. The context is read from its transcript via `agent-exec hook context --session <id> --agent <id>`. Every resumed turn re-reads the whole context, and cache reads count against the plan. Escape: `[orchestra:allow-resume: <reason>]` in the message, once per agent. Instead, spawn a fresh agent with a compact handoff: the goal, what was done and verified, what failed and why, the exact next step, and the files to read. | — |
| `hooks/guards/opt-in.ts` | New with the hooks-optin change, gated by `enforcement.opt_in`. Enforces "no orchestration without the user's opt-in" in a hook rather than in prose, which the instructor had already ignored. ORCHESTRATED work runs only when the user opted in: typed `/orchestra:run` or `/run`, asked for a workflow, or a prompt carrying ultracode. Without one, the Agent tool denies orchestra worker agents and generic agents that load `orchestra:run` in the same turn, and tells the instructor to ask the user once in one line, then stop. Once the user answers that ask, spawns are allowed whatever they said. Read-only Explore and Plan agents are never blocked, and cheap-model sessions, worker sessions and subagent callers are allowed. There is no prompt marker to lift it, because the model is the party it constrains. Escapes: `enforcement.opt_in` off, `ORCHESTRA_ENFORCEMENT=off`, and fail-open on any uncertainty. | — |
| `hooks/guards/land.ts` | New with the merge-guard change, gated by `enforcement.orchestra_merge` (on when absent). A `PreToolUse` Bash guard denying a merge, rebase, reset, cherry-pick or pull of an `orchestra/*` branch into a checkout that is not an orchestra worktree, and also a push, `update-ref`, a creating or forcing `branch`, and `checkout -b/-B` or `switch -c/-C` naming one (a push is denied even inside an orchestra worktree). Those integration commits are authored `orchestra` and must not reach the user's history. It also denies a merge or pull of an Agent `worktree-*` branch unless `--ff-only` (`--squash` included; the checked route is `isolate land --path`), and git calls inside shell loops, after `xargs`, or with variable operands (`$b`, `"$b"`, `$(…)`, backticks), where a variable operand counts every `orchestra/*` and `worktree-*` word in the command. The deny names `agent-exec isolate land --task <into> -m "<message>"` or `--path <worktree>`, which makes one commit with the user's identity. Read-only verbs and orchestra worktrees (where the runner and supervisors merge) are allowed. Escapes: `[orchestra:allow-orchestra-merge: reason]`, `enforcement.orchestra_merge` off, `ORCHESTRA_ENFORCEMENT=off`, and fail-open. | — |
| `hooks/lifecycle/cleanup-worktrees.ts` | On by default (`enforcement.session_cleanup: "on"`). A `SessionEnd` hook that removes the finishing session's orchestra worktrees (`agent-exec isolate remove --session <id>`), keeping any that still hold uncollected changes — a dirty worktree is the only record of what a worker tried. As of v0.30.0 this is a **backstop**, not the mechanism: the pipeline sweeps at run end instead, since a killed or crashed session never reaches `SessionEnd` at all. An unrecognized config value falls back to `"on"`; `ORCHESTRA_SESSION_CLEANUP=off` disables it regardless of config. | — |
| `examples/orchestra.yaml` | Sample configuration file (YAML, fully commented). Copy to `.claude/orchestra.yaml` (project) or `~/.claude/orchestra.yaml` (user) to override model tiers, declare external executors (now `enabled: true` by default), or set `enforcement.light_class`/`worker_vcs`/`turn_edits`/`session_cleanup`, or use `/setup` to author it interactively. | — |
